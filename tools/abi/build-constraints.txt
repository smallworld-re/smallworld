# Constraints for the build-isolation environment that generates the ABI tables.
#
# uv.lock does not cover build dependencies, so pypcode and angr are pinned in
# pyproject.toml's [build-system] requires, and their transitive dependencies
# are pinned here: a floating transitive dependency (for example pycparser 3
# under angr 9.2.x) breaks stage 1 at import time. uv applies this list from
# [tool.uv] build-constraint-dependencies in pyproject.toml, which must stay
# identical (tests/abi/packaging.py checks it). pip (25.3 or later) needs
#     pip install --build-constraint tools/abi/build-constraints.txt .
# or PIP_BUILD_CONSTRAINT set to this file's absolute path. Not
# PIP_CONSTRAINT: recent pip ignores it for build isolation, and it would
# also constrain the runtime install (pycparser, pypcode conflict there).
# pypa/build installs build requirements with its own pip call, so
# PIP_CONSTRAINT does apply to `python -m build` (CI uses that).
# nix builds from nix/abi-build-tools/uv.lock instead.
#
# Generic build tools (setuptools, cffi, numpy, typing-extensions,
# platformdirs) are left free, because these constraints apply to every
# package a build compiles from source, not only to smallworld.
#
# Regenerate after changing a pinned dependency set:
#     uv pip compile --python-version 3.10 <3.10 requires> and
#     uv pip compile --python-version 3.12 <3.12 requires>, then merge.
